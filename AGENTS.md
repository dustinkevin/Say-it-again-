## Supabase Database & Table Access Guidelines

앞으로 Supabase PostgreSQL 테이블을 생성하거나 마이그레이션 SQL을 작성 및 테이블에 액세스할 때는 아래 규칙을 **반드시** 적용한다.

### 1. PostgREST API 접근을 위한 명시적 GRANT SQL 포함
- `anon`과 `authenticated` 역할(Role)이 PostgREST API를 통해 테이블에 접근할 수 있도록 **명시적인 `GRANT` SQL 문**(`SELECT`, `INSERT`, `UPDATE`, `DELETE` 등)을 반드시 포함한다.
- `SERIAL` / `IDENTITY` 시퀀스를 사용하는 경우 시퀀스 권한(`USAGE, SELECT ON ALL SEQUENCES IN SCHEMA public`)도 함께 부여한다.

### 2. RLS(Row Level Security) 활성화 및 인증된 유저 전용 Policy 작성
- 모든 신규 테이블에 대해 **RLS(`ENABLE ROW LEVEL SECURITY`)를 반드시 활성화**한다.
- **인증된 유저(`authenticated`)만 읽고 쓸 수 있도록** `SELECT`, `INSERT`, `UPDATE`, `DELETE` 정책(Policy)을 함께 작성한다. (사용자 본인 소유 데이터인 경우 `auth.uid() = user_id` 조건 등을 명시적으로 검증한다.)

### 표준 SQL 템플릿 예시

```sql
-- 1. 테이블 생성
CREATE TABLE IF NOT EXISTS public.example_table (
  id BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
  user_id UUID NOT NULL REFERENCES auth.users(id) ON DELETE CASCADE,
  created_at TIMESTAMPTZ NOT NULL DEFAULT NOW()
);

-- 2. PostgREST API 접근을 위한 명시적 권한 부여
GRANT SELECT, INSERT, UPDATE, DELETE ON TABLE public.example_table TO anon, authenticated;
GRANT USAGE, SELECT ON ALL SEQUENCES IN SCHEMA public TO anon, authenticated;

-- 3. RLS(Row Level Security) 활성화
ALTER TABLE public.example_table ENABLE ROW LEVEL SECURITY;

-- 4. 인증된 유저(authenticated)만 읽고 쓸 수 있는 Policy 작성
CREATE POLICY "Authenticated users can select own rows"
  ON public.example_table
  FOR SELECT
  TO authenticated
  USING (auth.uid() = user_id);

CREATE POLICY "Authenticated users can insert own rows"
  ON public.example_table
  FOR INSERT
  TO authenticated
  WITH CHECK (auth.uid() = user_id);

CREATE POLICY "Authenticated users can update own rows"
  ON public.example_table
  FOR UPDATE
  TO authenticated
  USING (auth.uid() = user_id)
  WITH CHECK (auth.uid() = user_id);

CREATE POLICY "Authenticated users can delete own rows"
  ON public.example_table
  FOR DELETE
  TO authenticated
  USING (auth.uid() = user_id);
```
